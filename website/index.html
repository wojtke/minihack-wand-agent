MiniHack is built on the NetHack Learning Environment (NLE). All four clips are genuine recordings from the same frozen agent. Easy, Medium and Hard show complete successful episodes. Pro shows only the first 60 decisions of an episode; no success is implied. Playback is accelerated and the camera follows the player using only public game pixels. The labelled icons are cropped directly from native game renders. The four pictures are native game renders with terrain revealed in separate presentation-only instances. The agent and live game never receive these revealed views. Easy and Medium have fixed placements. Hard varies the player and wand positions in the starting area; Pro varies the wand position. Hard and Pro have an awake minotaur. MiniHack sets the default action limits to 50, 150, 400 and 1000. Reaching the limit ends the episode without success.

Easy: a successful wand attack

The policy chooses a discrete action index, which the environment maps to a keyboard input. The eight direction keys are k, l, j, h, u, n, b and y. The three other keys are comma (pick up), z (zap) and f (fire). During a prompt, the same key can select an inventory item or an aiming direction. In the example inventory the wand has letter f; z, f, l therefore means start using a wand, select it, then aim east. Moving into a monster can attack it. These are native single inputs, not scripted multi-step actions. MiniHack also has a Full variant with 85 inputs: 8 directions, 8 running directions, down, wait, more, 62 NetHack commands and 4 text characters. We use Restricted: the 8 directions plus pick up, zap and fire. The map is exposed as 21 by 79 arrays of glyph IDs, characters and colours. Other fields include inventory names and letters, game messages and character statistics. The pixel image is a rendering of this observation. Remembered terrain does not provide current information about unseen monsters. The quoted aiming prompt is an example from wand use, not a message from the pictured initial Pro state. These are native MiniHack/NLE rewards with no training bonuses. A frozen-step penalty of −0.01 is added whenever the game clock is unchanged, including menu interactions; this may also happen on a terminal step. The images are before and after the same recorded Easy episode. The last action kills the minotaur and earns +1. On Medium, Hard and Pro, killing the minotaur alone is not the success condition: the agent must reach the staircase.

The random agent draws one of the 11 Restricted inputs with equal probability at every step, including inputs that answer prompts. Nothing is learned and the rewards are the native MiniHack rewards. The four clips use seeds 950000000, 950010000, 950020000 and 950030000, chosen before recording; no seed was reselected. Pro shows only the first 150 of up to 1,000 actions. Playback is accelerated and cropped to the explored area. The table comes from a separate evaluation of 500 games per level on other seeds (16 October 2026). Easy succeeds only when the random inputs happen to form the wand sequence aimed at the minotaur. On Hard all 500 random games ended in death. On Pro 490 of 500 games reached the action limit; in the clip the agent stays near the start. With the Full set of 85 inputs, an earlier check of 100 games per level gave no successes on any level.

Plan

One agent for all four levels, trained with reinforcement learning.

Starting point
Double DQN. The network scores each of the 11 actions by the reward it expects to follow and picks the best one. Input: what the player can see — the map around the player, monsters, remembered items, inventory, health and the current prompt. One network for all levels, no level label.
Intermediate goal
One agent that solves Easy, Medium and Hard.
Final goal
The same agent also wins on Pro, where the wand has to be found in a maze. Ideas: memory (recurrent policy), example games from a scripted player.
Expected performance
Easy and Medium close to 100%, Hard around 80%, some wins on Pro.
Baseline
The random agent from the previous slide; later, our first Double DQN for every new method.
Metrics
Reward only says win or loss, so we also track: win rate on new games · how games end (minotaur, own ray, action limit) · wand picked up · squares explored · actions per win.
Double DQN estimates, for every action, the discounted reward that follows it and acts greedily on these values, with ε-greedy exploration during training. It learns from a replay buffer of past transitions and uses a slowly updated target network; the “double” variant chooses the next action with the online network and evaluates it with the target network, which reduces overestimation. The input is a 463-number encoding of public observations: a local map crop, visible monsters, remembered objects and exits, inventory, health, elapsed actions, the current prompt and previous inputs. The network has two hidden layers of 128 units and one output per action. One set of weights is used on every level and receives no level label. Pro is the hardest level: the wand is hidden in a maze, the minotaur is awake and the limit is 1,000 actions. Results are always measured on game seeds not used in training, with the game’s own reward; any training bonuses are removed for evaluation.

Move / aim

The live demo runs the original NLE engine in the browser, with the MiniHack task rules and native inputs. Hints are off by default and only explain controls; they do not perform actions. WASD moves north, west, south and east; Q/E/Z/C are diagonals. Arrow keys also work. P picks up, R starts wand use, and F fires or selects the wand during its inventory prompt. Space restarts the current level with the same seed; New game advances the seed. These browser shortcuts map to the same native inputs and do not change the agent’s action space. Press Escape to return keyboard control to the slides. Agent view (on by default) is centred on the player and shows only the policy’s inputs from experiments/wand_agent/features.py: a 9×9 window around the player with the agent’s own visit counts (blue tint), and outside it the positions of the three nearest remembered items, the two nearest staircases and the two nearest visible monsters. Item and monster types are not inputs. Markers beyond the view (12 squares sideways, 6 up or down) are drawn at its edge in their direction; the inputs themselves cap relative positions at 20 squares. The agent has no other memory of the explored map. Turn Agent view off to see the full remembered map that NetHack shows a human player.
